# Поиск максимума в слайсе

Программа один раз создаёт 100000000 случайных целых чисел в диапазоне
от 1 до 1000000. Затем ищет максимум вызовом `maximum`, потом вызовом `maxChunks` на том же слайсе. Если результаты расходятся, программа завершается с паникой.

## Запуск

В `go.mod` указана версия Go 1.24.1. Для запуска нужен Go этой версии или новее.
Команды выполняются из корня проекта:

```sh
go run .
```

На 64-битной системе слайс занимает около 763 МБ. Дополнительная память
нужна для среды выполнения Go и горутин. При разбиении слайса элементы не копируются.

## Как работает поиск

`maximum` последовательно просматривает все элементы. `maxChunks` использует
целочисленное деление: первые семь частей получают по `len(data) / 8` элементов,
восьмая забирает оставшиеся элементы. Каждая часть обрабатывается в отдельной горутине.

Горутины записывают максимумы в разные элементы слайса результатов, поэтому
мьютекс не нужен. После ожидания через `WaitGroup` функция находит общий максимум.
Обе функции работают с отрицательными числами и возвращают 0 для пустого входа.

## Проверки

```sh
go test -count=1 -timeout=60s ./...
go vet ./...
```

## Сравнение производительности

Программа выводит время каждого поиска в микросекундах. Генерация входа
и печать результатов не входят в замеры. Замер `maxChunks` включает подготовку
частичных результатов, запуск горутин, ожидание и итоговый поиск.

Для повторных замеров:

```sh
go test -run '^$' -bench '^Benchmark(Maximum|MaxChunks)$' -benchmem -count=3 -cpu=1,8 ./...
```

Бенчмарки `BenchmarkMaximum` и `BenchmarkMaxChunks` используют наборы
из 1000, 1000000 и 10000000 элементов. Обе функции получают одинаковые
воспроизводимые данные, подготовка входа не входит в замер.

Флаг `-cpu=1,8` задаёт `GOMAXPROCS=1` и `GOMAXPROCS=8`.
Для непустого входа `maxChunks` запускает восемь горутин в обоих случаях,
при значении 1 одновременно исполняется только одна из них. `-count=3` повторяет каждый бенчмарк три раза, `-benchmem` показывает затраты памяти внутри замера.
